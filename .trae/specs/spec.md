# 密码管理器服务 - 规格说明 (spec.md)

## 1. 问题陈述

用户需要一个自托管的密码管理服务，类似 Google Password Manager，能够跨多个平台（PC、Mac、Android、浏览器、iPhone、TV、Linux、Linux Server）安全地存储和同步密码数据。该服务需要提供统一的 REST API 接口，支持 API Key 认证，并能够部署到 Cloudflare Workers 上，使用 Cloudflare KV 命名空间作为数据存储后端。

## 2. 目标用户

- **个人用户**：需要在多设备间同步个人密码的技术用户
- **开发者**：需要通过 API 集成密码管理功能的开发者
- **小型团队**：需要简单、自托管的团队密码共享方案

## 3. 项目目标

### 3.1 主要目标
1. 提供安全的端到端密码存储服务
2. 支持多平台数据同步（通过统一 REST API）
3. 支持 API Key 认证机制
4. 可部署到 Cloudflare Workers + KV
5. 提供 Web 管理界面（Dashboard）

### 3.2 非目标
1. **不**包含浏览器扩展插件开发（仅提供 API，扩展由用户自行开发）
2. **不**包含原生移动应用开发（Android/iOS/TV 应用通过 API 对接）
3. **不**提供密码共享/协作功能（v1 仅支持单用户）
4. **不**实现复杂的 RBAC 权限系统（v1 仅支持单 API Key 用户）
5. **不**实现双因素认证（2FA）（v1 仅使用 API Key）

## 4. 功能需求 (Functional Requirements)

### 4.1 认证与授权
- **FR-1**: 支持 API Key 认证，所有 API 请求必须携带有效 API Key
- **FR-2**: API Key 通过 `X-API-Key` 请求头传递
- **FR-3**: 提供初始化接口，用于设置主密码并生成初始 API Key
- **FR-4**: 支持 API Key 的吊销和重新生成

### 4.2 密码条目管理
- **FR-5**: 创建密码条目（包含：网站/服务名、URL、用户名、密码、备注、标签、分类）
- **FR-6**: 查询单个密码条目（按 ID）
- **FR-7**: 查询密码条目列表（支持分页、搜索、按标签/分类过滤）
- **FR-8**: 更新密码条目
- **FR-9**: 删除密码条目（软删除，支持回收站）
- **FR-10**: 恢复已删除的密码条目
- **FR-11**: 永久删除密码条目

### 4.3 分类与标签
- **FR-12**: 创建/查询/更新/删除分类
- **FR-13**: 创建/查询/更新/删除标签
- **FR-14**: 为密码条目添加/移除多个标签

### 4.4 密码生成器
- **FR-15**: 提供服务端密码生成 API，支持自定义长度、字符集配置
- **FR-16**: 提供密码强度评估 API

### 4.5 数据加密
- **FR-17**: 所有敏感字段（密码、备注）在存储前使用 AES-256-GCM 加密
- **FR-18**: 加密密钥由用户主密码派生（PBKDF2，100,000+ 迭代）
- **FR-19**: 服务端**不存储**用户主密码的明文或可还原形式
- **FR-20**: 每个密码条目使用独立的随机 IV（初始化向量）

### 4.6 数据同步
- **FR-21**: 提供增量同步 API（按 `updated_at` 时间戳拉取变更）
- **FR-22**: 支持批量导入/导出（JSON 格式）
- **FR-23**: 每个条目包含 `created_at`、`updated_at`、`version` 字段用于冲突检测

### 4.7 Web 管理界面
- **FR-24**: 提供登录页（输入主密码解锁）
- **FR-25**: 提供密码列表视图（支持搜索、分类过滤、标签过滤）
- **FR-26**: 提供密码条目详情/编辑/创建表单
- **FR-27**: 提供分类和标签管理页面
- **FR-28**: 提供 API Key 管理页面（查看、吊销、重新生成）
- **FR-29**: 提供设置页面（主密码修改、导入/导出）

### 4.8 API 文档
- **FR-30**: 提供 OpenAPI/Swagger 格式的 API 文档页面

## 5. 非功能需求 (Non-Functional Requirements)

### 5.1 安全
- **NFR-1**: 所有 API 通信必须使用 HTTPS（生产环境）
- **NFR-2**: 密码字段绝不在响应日志或错误信息中出现
- **NFR-3**: API Key 使用安全随机数生成（至少 32 字节熵）
- **NFR-4**: 对失败的认证请求进行速率限制（防止暴力破解）
- **NFR-5**: 支持 CORS 配置，允许浏览器端调用

### 5.2 性能
- **NFR-6**: 单 API 请求响应时间 < 500ms（在 Cloudflare Workers 边缘网络）
- **NFR-7**: 支持至少 10,000 条密码条目而不显著降低性能
- **NFR-8**: KV 读取使用缓存策略减少冷启动延迟

### 5.3 兼容性
- **NFR-9**: API 遵循 RESTful 设计原则，易于各平台客户端集成
- **NFR-10**: 所有 API 输入/输出使用 JSON 格式
- **NFR-11**: 支持跨域请求（CORS），浏览器端可直接调用
- **NFR-12**: 加密算法使用 Web Crypto API / Node.js Crypto 标准实现，跨平台兼容

### 5.4 部署与运维
- **NFR-13**: 整个应用可通过 `wrangler deploy` 一键部署到 Cloudflare Workers
- **NFR-14**: 使用环境变量配置敏感信息（不硬编码）
- **NFR-15**: 提供清晰的部署文档和配置说明
- **NFR-16**: 本地开发模式支持模拟 KV 存储（无需 Cloudflare 账号即可开发）

## 6. 约束条件

| 约束 | 说明 |
|------|------|
| **部署平台** | 必须可部署到 Cloudflare Workers |
| **存储后端** | 必须使用 Cloudflare KV 命名空间 |
| **前端框架** | 使用 Next.js 16 App Router + React 19 |
| **样式方案** | 使用 Tailwind CSS 4 |
| **语言** | TypeScript（严格模式） |
| **运行时** | 不使用已弃用的 Edge Runtime，使用标准 runtime |
| **中间件** | 使用 `proxy.ts`（Next.js 16 已弃用 `middleware.ts`） |
| **KV 限制** | 单 KV value <= 25MB，Keys 数量无限制（免费版有存储限制） |

## 7. 依赖项

| 依赖 | 用途 | 必要性 |
|------|------|--------|
| `next` v16.3.6+ | 应用框架 | 必需（已安装） |

| `tailwindcss` v4+ | 样式 | 必需（已安装） |

## 8. 假设

1. 用户已具备 Cloudflare 账号，能够创建 Workers 和 KV 命名空间
2. 用户理解 API Key 的安全风险，会妥善保管自己的 API Key
3. v1 版本为单用户设计，不考虑多租户隔离
4. 客户端（浏览器扩展、移动端 App）由用户自行开发或使用第三方工具
5. 主密码丢失将导致数据不可恢复（服务端不存储可还原信息）

## 9. 待决问题 (Open Questions)

1. **Q1**: 是否需要支持密码附件（如 SSH 私钥文件）？ → v1 暂不支持，仅文本备注
2. **Q2**: 是否需要密码共享/多用户协作？ → v1 暂不支持，仅单用户
3. **Q3**: 是否需要审计日志（记录每次 API 访问）？ → v1 可选，列入低优先级
4. **Q4**: 是否需要密码过期提醒？ → v1 可选，列入低优先级

## 10. 验收标准 (Acceptance Criteria)

### Rule 类型（可客观验证的二元条件）

| AC ID | 验收标准 | 验证方式 |
|-------|---------|---------|
| **AC-R1** | `POST /api/auth/init` 能接受主密码并返回有效的 API Key，且第二次调用返回错误（已初始化） | 手动测试 + curl |
| **AC-R2** | 未携带 `X-API-Key` 头的 API 请求返回 401 状态码 | 手动测试 + curl |
| **AC-R3** | 携带无效 API Key 的请求返回 401 状态码 | 手动测试 + curl |
| **AC-R4** | `POST /api/passwords` 创建条目后，`GET /api/passwords/:id` 能正确读取 | 集成测试 |
| **AC-R5** | `PUT /api/passwords/:id` 更新后，`version` 字段递增 | 集成测试 |
| **AC-R6** | `DELETE /api/passwords/:id` 为软删除，`GET /api/passwords` 默认不包含，`GET /api/passwords?trashed=true` 可查询到 | 集成测试 |
| **AC-R7** | 从 KV 直接读取的密码值为密文（不可直接识别为明文密码） | 手动检查 KV 数据 |
| **AC-R8** | 相同主密码 + 相同明文，两次加密得到不同的密文（IV 随机） | 单元测试 |
| **AC-R9** | `GET /api/passwords?search=xxx` 能按网站名、URL、用户名进行模糊搜索 | 集成测试 |
| **AC-R10** | `GET /api/passwords/sync?since=timestamp` 只返回该时间后创建/修改/删除的条目 | 集成测试 |
| **AC-R11** | 项目根目录存在 `wrangler.toml` 配置文件，定义了 KV 命名空间绑定 | 检查文件 |
| **AC-R12** | `npm run build` 构建无错误 | 命令执行 |
| **AC-R13** | Web 登录页输入正确主密码后能进入 Dashboard | 手动测试 |
| **AC-R14** | Dashboard 可创建、编辑、删除密码条目，操作后列表实时更新 | 手动测试 |
| **AC-R15** | API 文档页面可访问，展示所有接口定义 | 手动测试 |
| **AC-R16** | CORS 预检请求（OPTIONS）返回正确的响应头 | curl 测试 |

### Rubric 类型（评估性质量维度）

| AC ID | 维度 | 评分标准 (0-2) | 及格线 | 证据来源 |
|-------|------|---------------|--------|---------|
| **AC-S1** | **代码结构清晰度** | 2 = 模块分层清晰（API 层 / Service 层 / 存储层 / 加密层），职责单一；1 = 分层存在但边界模糊；0 = 所有逻辑混在一起 | ≥ 1 | 代码审查 |
| **AC-S2** | **安全实现质量** | 2 = 加密符合行业最佳实践（AES-256-GCM + PBKDF2/Argon2，随机 IV，无明文泄漏）；1 = 加密实现但有轻微不足；0 = 存在明文存储或明显漏洞 | ≥ 2 | 代码审查 + 安全测试 |
| **AC-S3** | **API 设计一致性** | 2 = RESTful 风格统一，状态码、错误格式、分页、过滤参数一致；1 = 基本一致但有少量不一致；0 = 接口风格混乱 | ≥ 1 | API 审查 |
| **AC-S4** | **部署友好度** | 2 = 有完整 wrangler.toml + 环境变量说明 + 一键部署脚本/文档；1 = 有基本配置但缺少说明；0 = 无法直接部署 | ≥ 1 | 配置审查 |
| **AC-S5** | **UI/UX 可用性** | 2 = 界面美观、操作流畅、移动端响应式适配良好；1 = 功能可用但交互粗糙；0 = 功能不完整或严重不可用 | ≥ 1 | 手动测试 |
